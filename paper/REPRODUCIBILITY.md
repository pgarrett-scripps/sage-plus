# Chapter analysis and regeneration

Operational provenance and build instructions are retained here rather than in
the dissertation appendix.

The original evidence is described in
[`benchmarks/scientific-results/20260914/README.md`](../benchmarks/scientific-results/20260914/README.md).
That record retains executable identities, archive checks, original failures,
and the distinction between local evidence and public deposition. Large spectra
remain external to the archive and are identified by receipts and manifests.

The worker-scaling and LFQ extension plan is
`analysis/data/report-extension/plan.json`. Its execution directory is
`/data/sage-plus-scientific/report-extension-20260915`. The runner records
executable and input hashes, commands, process limits, output identities, and
completion states. LFQ has one search per engine. Worker scaling has one warmup
and three measured trials per engine and worker count. The closing audit is
`analysis/data/report-extension/verification.json`.

`analysis/scripts/collect_report.py` normalizes retained outputs from both
engines without modifying the original pilot. It checks disagreement counts
against the frozen engine-only counts and quantitative ratio counts against
the common scientific metric function. Shared LFQ sets use identical peptide,
charge, and preparation keys. These extensions are post hoc and add no
independent biological studies.

From `paper/`, regenerate and verify the chapter with:

```bash
just assets
just fmt
just docx
just paper
just verify
just check-stats-deep
```

The build reads frozen summaries and does not run biological searches. To
regenerate the report snapshots from retained outputs, run from `paper/analysis/`:

```bash
uv run scripts/collect_report.py public
uv run scripts/collect_report.py ptm
uv run scripts/collect_report.py lfq
uv run scripts/collect_report.py scaling
uv run scripts/collect_matched_fdp.py
```

The nineteen chapter figures share typography, colors, line styles, and export
settings in `analysis/scripts/_figure_style.py`. The report, scientific, endpoint, and supplement
figure generators produce 360 dpi PNGs for the chapter and scalable SVG
companions in `figures/vector/`. Both formats are regenerated by `just assets`.
Captions describe the plotted summaries, reference lines, and axis scales.

The matched-FDP analysis evaluates every observed peptide q-value step. It keeps
whole q-value ties, uses the conservative paired bound for score ties, and checks
the original audited operating points and each selected operating point against
the direct estimator. Input hashes are checked against the retained calibration
records. The chosen thresholds are in `analysis/data/matched-fdp.json`, which
also records the hash of the complete curves retained locally in
`analysis/results/matched-fdp-curves.json.gz`. Its scientific limitation is reuse of the same
entrapment observations for threshold selection and error estimation.

The focused estimator checks run from `paper/`:

```bash
uv run python tests/test_matched_fdp.py
```

For new searches, consult `../benchmarks/SCIENTIFIC_PILOT.md`, supply the pinned
executables and verified inputs, and use a new output directory. Never overwrite
the frozen evidence or assign an evaluated release identity to a changed binary.

## Proposed concurrent throughput experiment

This experiment was deferred on September 18, 2026 because available host memory
was below the existing runner's 8 GiB minimum and swap was nearly full. No
concurrent throughput result is claimed. The resource observation is retained in
`analysis/data/concurrency-feasibility.json`.

Use the same four PXD028735 mixture files in their original order: A Alpha,
B Alpha, A Beta, and B Beta. Use the frozen Sage and Sage Plus executables and
the amended `hye-irt-defined.fasta` reference. Keep the original identification
settings and process limits, with one file per search and LFQ disabled.

Compare these schedules at a total budget of eight Rayon workers:

| Concurrent searches | Workers per search | Scheduling |
| --- | --- | --- |
| 1 | 8 | Four files sequentially |
| 2 | 4 | Two initial files, replace each finished search with the next file |
| 4 | 2 | All four files concurrently |

Run one warmup batch and three measured batches for each engine and schedule.
Alternate engine order and rotate schedule order across measured rounds. Run
only one batch at a time. The full matrix has 24 batches and 96 individual
searches, including warmups. Record failures explicitly and do not substitute
partial batches for completed batches.

Measure batch wall time from first launch through last successful process exit.
Calculate files per hour as `4 * 3600 / batch_seconds`. Sample the simultaneous
sum of resident memory for all search processes and descendants at a declared
interval, such as 10 milliseconds, and report its maximum as sampled aggregate
RSS. Do not sum individual process peaks, which can occur at different times.
Retain the actual sample intervals and all per-search logs, configurations,
commands, return codes, and input and output hashes. Report shared-page double
counting as a limitation of aggregate RSS. Confirm no swap activity during
measured batches and sufficient free memory before the experiment begins.

Report medians and measured ranges for all three endpoints. Use one figure only
if the completed experiment adds a clear result. Keep the existing six main
figures until then.

The main-text timing, PSM agreement, and LFQ endpoint plots replace numeric
tables with comparative figures. Their original exact-value tables remain in
the Supporting Information, with references from the corresponding captions.
The endpoint plots use the same frozen inputs and do not change the analyses.

Seven supplemental comparisons are presented as figures instead of tables. The
redundant primary FDP summary table is omitted from the document because the
main text and calibration figures already report it. Five exact-value reference
tables are collected in the final SI section, Tables. All original generated
table assets and frozen machine-readable inputs remain in the repository for
reproducibility, including tables no longer printed in the chapter.
